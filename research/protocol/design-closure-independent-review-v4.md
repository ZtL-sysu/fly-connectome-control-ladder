## Design-level assessment

- **Global new-arc compatibility:** The executable specification now forms the union of all possible new arcs in each retained block’s selected stratum and rejects blocks whose union overlaps an already retained block. This conservative, response-independent rule makes independently selected block matchings safe from cross-block duplicate arcs. It is sound as a design rule. Its practical cost is unknown: rejection counts, the resulting complete-mask support, and support at each dose must be materialized and checked before proceeding; sampled block counts do not establish these properties.
- **Four-candidate response selection:** Pairwise response features propose four complete masks over the same edited rows and shared binned geometry. The selected response mask is then chosen using the full-mask aggregate forcing objective, including shared targets and gray/development clips. This correctly avoids treating summed pairwise scores as the final objective. Four candidates are a bounded heuristic and can miss cancellation patterns; no optimality or response benefit is established. Preserve every candidate, score, duplicate, and rejection, with no outcome-driven expansion.
- **Edited-edge mass:** All arms use a common graph-only block prefix at each dose; blocks are indivisible, realized dose and maximum block error are reported, and unreached targets are ineligible. Transferred masks retain their source-selected prefix. This is a coherent equal-support design, conditional on actual active-mass accounting and adequate support. No active-dose result has been measured.
- **Geometry control:** The approximate joint binned signature is explicitly defined and versioned. It should not be described as exact geometric equivalence. The strong geometry arm minimizes exact source separation within common binned support, and the specified raw-geometry diagnostics and absolute SMD threshold of .1 make residual imbalance visible. The .1 criterion is an operational balance rule, not proof that geometry or biological confounding is absent. Whole-mask raw geometry distributions, boundary associations, within-bin balance, and the required diagnostics still need to be generated; the 300-block screen establishes none of these at dose level.
- **Inference and scope:** The closure’s K=45 count is internally consistent: three mandatory arms, seven E1 gates per arm (21), and eight E2 gates per arm (24), with one-sided Bonferroni family-wise alpha .05. Freeze endpoints, bootstrap/clustering units, identities, and K before confirmation. These claims support conditional fixed-panel inference and finite-ensemble sensitivity analysis, not an independent biological or initialization population. E2 is a continuous half-margin forecast-error criterion, not a classification claim. The source/split caveats and withheld Sintel TEST labels appropriately constrain interpretation.
- **Noise reference:** The selected noise-only reference is specified as std .08 on normalized rendered receptor luminance, lower-clamp only, before nearest-exact resampling, with other stochastic transforms disabled. Treat .08 as the code standard deviation, not a variance. Four development draws are a provisional finite calibration budget; retain seeds, realized-array hashes, clipping fractions, and calibration cells. Historical noise draws are not evidenced, and the archived source split provenance remains unresolved; the stated conservative development exposure should govern.

## Remaining startup gates

These are distinct from later scientific pilot checks:

1. **Static construction artifact:** Execute the v3 constructor against the pinned graph and emit a complete support/rejection report after global-union filtering, with per-dose reachable support, shared edited-edge identities, topology certificates, realized mass, and raw-geometry/SMD diagnostics. The sampled structural screen and reciprocal-pair witness do not substitute for this artifact.
2. **Runtime parameter-group map:** Verify the actual checkpoint’s edge-row-to-parameter-group mapping and conservation on the constructed graph. The static export’s label-derived groups do not prove the runtime array mapping; rebuilding the Connectome recomputes `du,dv`. The acute surgery must carry original row parameter assignments unchanged.
3. **Canonicalization and device restore:** Demonstrate a source-faithful restore on the intended device, including the required post-load projections for network parameters and decoder hex-convolution masks. Preserve raw and projected hashes, then confirm parameters and BatchNorm buffers do not mutate during inference. The official device default is CUDA-or-CPU; local MPS availability is not evidence that the full Flyvis path runs on MPS.
4. **Measured resource profile:** Measure forward, decoder projection/restore, and proposal-search time and actual peak allocated/reserved memory using the bounded inference shape and verified device. The existing report is static byte/operation-count plausibility only; it supplies no measured runtime, peak memory, or successful restore. Novix tasks 21892 and 21897 failed at steps 0 with `ControlPlaneFailure`; a subsequent read-only get returned code 5000. No profile/result is available, and these failures establish neither latency nor billing. A successful profile is still required through a functioning route.

The first three gates establish constructor and model compatibility; the fourth establishes operational feasibility. Once those pass, guidance may authorize the bounded development pilot. Empirical common support at useful doses, active-dose informativeness, control separation, noise-scale stability, and confirmation precision are subsequent P2 pilot/precision gates, not demonstrated startup properties. Keep the four GPU-hour/two-task pilot cap and stop rules binding.
