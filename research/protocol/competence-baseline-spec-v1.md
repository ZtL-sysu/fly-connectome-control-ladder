# Competence baseline specification — proposed before any task result

Owner: ccf-experiment-designer. This closes the input-only baseline placeholder for review. No coefficients, metrics or scientific model outputs have been computed.

Reference competence is a prerequisite for interpreting function preservation, not an optical-flow leaderboard claim. Report native source EPE and l2norm in the source-rendered normalized target units. Apply the audited image/flow alignment, spatial sum/mean filters and timing to every baseline. Use the same fixed development scenes and initial gray history; official TEST labels are unavailable and cannot qualify competence.

Baselines: (1) zero flow; (2) a two-channel spatially constant flow vector fitted as the training-scene mean under leave-one-development-scene-out evaluation; (3) a shared, input-only local temporal ridge regressor. The third reads rendered luminance only, no neuron states, graph, decoder, checkpoint values or future input.

For the input-only baseline, use the current and previous **distinct source-frame** luminance, mapped causally through the known nearest-exact resampling schedule. Before the first observed source frame, previous luminance is gray.5. Do not give this baseline the discarded raw first image or future source frames. Use twelve shared per-hexal features: current/previous luminance; their difference; current/previous finite differences along the two hex axes; products of the temporal difference with each current spatial derivative; a bias; and two flags indicating whether both neighbors are available along each axis. Central differences use both neighbors, one-sided differences use the available neighbor, and missing directions return0. The two output channels are regressed directly in source target units, avoiding guessed physical-unit conversions.

Fit one coefficient vector per flow channel shared across hexals. Normalize nonconstant feature columns on training scenes only. Ridge alpha grid is0,.001,.01,.1,1,10,100; select by nested scene-level development validation, with a pseudoinverse/least-squares solve at alpha0. Include all predefined clips from a scene in one fold. Baselines used to qualify an evaluated development scene are trained without that scene. Freeze preprocessing, coefficient-selection rule and all results; do not choose a weaker input-only baseline after inspecting reference performance.

These small analytical fits are separate comparator fitting, not reference/null neural or decoder training. Their compute/search is part of the finite pilot budget; no reference/null optimizer exists. Source-response graph matching and noise calibration do not read flow labels. No comparator is fitted on confirmation query outcomes or labels.

The operational pilot criterion is lower paired development EPE for the fixed reference than each of the three controls, with scene-level uncertainty reported. Unresolved/worse competence blocks interpretation and returns the design to review; do not select favorable checkpoint identities from the50-model ensemble. The proposed initial solutions000/001 and later receiving panel are fixed before task evaluation. Receiving models remain in the declared panel even if competence is poor; failures are not silently excluded from final evidence.

This is a deliberately small input-only sanity baseline. The authoritative recent model baseline is the full pretrained Flyvis network plus its trained DecoderGAVP; TopoSens-style constrained degree swapping and the explicit geometry/magnitude/shuffle controls answer the graph-intervention question. Literature-only pruning/retrained-model studies cannot be presented as exact reruns of this different estimand. Scientific prototype/competence checks still require ordered guidance/research gates and an authorized execution route.
